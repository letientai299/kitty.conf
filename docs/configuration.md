# Configuration and local preferences

`conf/kitty.conf` owns rendering, memory, window behavior, tab layout, and include
order. `conf/keys.conf` owns shared shortcuts. `conf/colors.conf` supplies the
Carbonfox fallback palette. `conf/mac.conf` owns macOS behavior and shortcuts.
Kitty requires separate `open-actions.conf` and `quick-access-terminal.conf`
entry points for URL actions and the quick-access terminal.

The [Kitty configuration reference][config] defines includes and defaults.
The launcher still loads `mac.conf` after `kitty.conf` on macOS; no Linux-specific
layer is required for the shared defaults.

## Local files

All personal settings live in ignored `conf/local/` files. Missing files are
allowed. A fresh clone uses the system monospace font at 15 points and Carbonfox.
The custom tab renderer may show missing folder glyphs without a Nerd Font;
that is a renderer portability issue, separate from font selection.

| File                     | Purpose                                              | Precedence              |
| ------------------------ | ---------------------------------------------------- | ----------------------- |
| `local/machine.conf`     | Font family and machine preferences                  | After shared defaults   |
| `local/theme.conf`       | Selected theme or include generated by themes kitten | After machine settings  |
| `local/preferences.conf` | Saved font size and proposed zoom metadata           | After theme             |
| `local/mac.conf`         | Optional macOS overrides                             | Last, inside `mac.conf` |

The local macOS override is intended for platform settings and keys; avoid
putting managed font size or palette values there. Configuration is shared by
instances launched from this checkout. Another checkout has separate local
preferences. Clone and install tools on another machine; select its font locally
instead of copying a machine-specific font requirement through Git.

The previous Iosevka selection and Carbonfox palette were preserved in this
machine's ignored files. The previous automatic no-preference palette was saved
as `local/previous-no-preference.conf`; it is not loaded automatically. This
removes an implicit OS-driven override of the explicitly selected theme.

## Save a theme or font now

Open the command palette with `ctrl+shift+f3` and select `kt_theme` to
launch the theme picker in an overlay.

Run these commands inside a `kt` instance:

```sh
kt theme
# Or select by name:
kt theme "Carbonfox"
kitten choose-fonts --config-file-name local/machine.conf --reload-in parent
```

`kt theme` creates the local directory and launches the [themes kitten][themes],
which writes its selected palette and an include. Giving
it the local directory keeps both files together and out of Git. Merely passing
`--config-file-name local/theme.conf` with the original config directory is
insufficient: Kitty's theme writer places `current-theme.conf` at the config
root but writes a relative include. See the [theme writer][theme-writer].

The [font chooser][fonts] writes only the local machine file. If a managed
`local/preferences.conf` exists, its effective font size wins; use the future
size command described below to change that value. Font family still comes
from the chooser.

Reload manually after creating a local file for the first time. Existing-file
changes use Kitty's normal reload behavior. Saved themes and font settings
survive subsequent reloads and launches. Avoid running the kittens with their
default config-file target, which edits tracked `kitty.conf`.

For a persistent size today, set `font_size 16` in `local/preferences.conf`, then
reload. Stock zoom shortcuts still change runtime state only. The command design
below is needed to make those shortcuts persistent automatically.

## Persistent zoom design

The size and zoom commands below are proposals. Theme selection through
`kt theme` is implemented.

Kitty's [font-size action][boss] changes in-memory sizes. Its config reload
reapplies the configured size. There is no separate persistent zoom setting in
Kitty: represent terminal text zoom as `effective_points = base_points * scale`.
This is independent of macOS display scaling and Chrome zoom.

Proposed commands:

| Command                         | Saved behavior                                       |
| ------------------------------- | ---------------------------------------------------- |
| `kt font-size 16`               | Save 16-point base size and reset scale to 1         |
| `kt zoom +0.1` / `kt zoom -0.1` | Adjust the saved scale by 10 percentage points       |
| `kt zoom reset`                 | Restore scale 1 while keeping the selected base size |

Use one authoritative `local/preferences.conf` file:

```conf
# kt.base_font_size 16
# kt.zoom_scale 1.25
font_size 20
```

Kitty reads the effective size; Go reads and updates the metadata. Missing
metadata means base equals the existing size and scale equals 1. Missing file
means the shared 15-point default and scale 1. Reject malformed or non-finite
numbers without changing the file. Validate effective sizes against Kitty's
supported limits and round consistently.

A command must lock a stable sidecar file, read the latest saved values, compute
the new state, and atomically rename a temporary file in the same directory.
Do not lock the file that gets replaced. Preserve the previous contents on
validation/write failure. Concurrent hotkeys and different instances must not
lose updates.

Persist before applying the live change through the current instance socket.
Use an absolute effective size for `set-font-size`; do not replay relative zoom
after saving it. Report apply failure while retaining the saved preference.
Other instances using this checkout converge on reload; never broadcast to
unrelated global-config instances. New instances use the saved effective size.

Theme selection already delegates saving and reload to Kitty’s native picker.
The proposed size writer must make size durable before a later theme change
reloads the configuration. Keep task/session data in the temporary state
directory; preferences must never live there.

After implementing the commands, remap Ctrl+Shift+Plus/Equal/Minus/Backspace and
the corresponding macOS Cmd zoom keys to them. Account for menu/font actions
and arbitrary remote `set-font-size` calls: these bypass the saved state and
remain temporary unless explicitly routed through the same writer. Do not
promise persistence for changes the command never observes.

Acceptance: saved theme and effective font size survive reload, restart, and
changing theme after zoom; missing files use defaults; concurrent increments
compose; failed writes do not change live state; no tracked file changes;
unrelated Kitty instances are untouched. Test both file parsing and a live
instance. Add key bindings only after the command exists.

## Power and memory defaults

The existing 20 ms repaint delay and 6 ms input delay remain. They trade some
throughput/responsiveness for fewer updates; 20 ms is not a strict FPS cap when
input forces a repaint. Vsync remains enabled. See [Kitty performance][perf].

Cursor blinking is disabled and the quick-access terminal is opaque. Pager
history is capped at 64 MiB per pane, down from 256 MiB; interactive scrollback
stays at 10,000 lines. This reduces the maximum retained pager history, so fewer
old lines are available in long, busy sessions. History-cap changes affect new
panes. Put `scrollback_pager_history_size 256` in `local/machine.conf` if needed.

Keep cursor trails, blink easing, background blur, and dynamic opacity disabled
at their defaults. Keep resize debouncing at its default. Disabling ligatures,
URL detection, or vsync is not a demonstrated power improvement for this setup;
retain those features unless a workload measurement supports changing them.

No battery-life percentage is claimed. Compare idle shell, active TUI, output
flood, pane count, and quick-access workloads at fixed screen brightness and
refresh rate. Record CPU, GPU/energy impact, memory, and typing responsiveness.
Chrome activity must remain comparable between runs.
